# 개발 기록 — 실행 관리 홈페이지 (launcher)

이 앱을 고치기 전에 읽고, 고친 뒤에는 같은 커밋에서 이 파일도 고칩니다. 규칙은 저장소 최상위 [`CLAUDE.md`](../CLAUDE.md)에 있습니다.

## 개발 방향 — 바꾸려면 먼저 합의

| 원칙 | 내용 |
| --- | --- |
| 한 화면, 두 모드 | 같은 `public/`이 ① 온라인(GitHub Pages: 웹 데모 링크와 실행 안내) ② 로컬 런처(`server.js`: 실행·중지·진행률·로그) 두 모드로 동작합니다. `api/apps`가 응답하면 로컬, 아니면 온라인입니다. |
| 프로그램마다 두 가지 방법 | 카드마다 "① 웹에서 바로 실행"과 "② 내려받아 실행"을 함께 보여 줍니다. |
| 의존성 없음 | 런처는 Node.js 기본 모듈만 씁니다. 처음 받은 사람도 `START.cmd` 하나로 켜져야 합니다. 프로그램별 패키지는 실행할 때 그 폴더에서 `npm ci`로 설치합니다. |
| 이 PC 안에서만 | `127.0.0.1`에만 열고, 주소 이름(Host)·출처를 확인하며, 실행·중지 요청은 `X-Launcher` 헤더가 있어야 받습니다. |
| 다음 할 일을 주 버튼으로 | 상태마다 주 버튼이 바뀝니다(실행 → 취소 → 열기). 진행 상황(단계·진행률·경과 시간)을 항상 보여 줍니다. |
| 안전한 화면 | 로그·계정 등 바깥에서 온 문자열은 `textContent`로만 넣습니다. 바뀐 부분만 다시 그려 복사 버튼의 초점을 지킵니다. |
| 확인 방법 | 런처를 띄워 실행·설치·중지를 직접 해 보고, 온라인 모드는 Pages와 같은 구조로 조립해 확인합니다. CI(`ci.yml`의 런처 작업)는 런처가 뜨고 API가 응답하는지만 봅니다. |

## 진행 중

지금 진행 중인 작업이 없습니다. 작업을 시작하면 아래 "다음 할 일"에서 이곳으로 옮기고, 끝나면 "완료 기록"으로 옮깁니다.

## 다음 할 일 (우선순위순)

### 보통

- [ ] damage(서버 모드)의 첫 임시 비밀번호는 런처 메모리에만 있어 런처를 다시 켜면 사라짐 — `server.js`의 `account`. → 첫 실행 때 안내 파일로 남기거나 재설정 버튼 검토.
- [ ] 설치 진행률이 npm 로그 형식(`npm http fetch` / `npm http cache`)에 기대고 있음 — 형식이 바뀌면 진행 중 애니메이션으로만 보임(설치는 정상).
- [ ] 포트(3000·5173·3210·8080)를 화면에서 바꿀 수 없음 — 다른 프로그램과 겹치면 환경변수나 코드로 바꿔야 함.
- [ ] 다른 창에서 이미 실행 중인 프로그램(예: 3210의 센서로그)을 런처에서 끌 수 없음 — "열기"만 가능.
- [ ] 런처 자동 시험이 없음(실행·설치·중지 흐름은 손으로 확인).

### 나중에

## 완료 기록

### 2026-10-20

- 런처 처음 만듦 — 두 프로그램 실행·중지, 첫 실행 때 자동 설치, 로그·초기 계정 보기, `START.cmd`·`start.sh`·`npm start`.
- 사용성 개선 — 설치 → 시작 → 열기 단계와 진행률·경과 시간, 상태별 주 버튼, 모두 중지, 주소·계정·로그 복사, 준비되면 알림과 탭 제목 표시, 오류 시 로그 자동 펼침, 런처 연결 끊김 안내. 온라인 모드에 ZIP 내려받기, OS별 안내, 자주 묻는 질문.
- 프로그램마다 "① 웹에서 바로 실행 / ② 내려받아 실행" 카드, 센서로그 웹 데모 링크, 깊은 주소용 `public/404.html`.
