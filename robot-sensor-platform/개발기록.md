# 개발 기록 — 센서로그 (robot-sensor-platform)

이 앱을 고치기 전에 읽고, 고친 뒤에는 같은 커밋에서 이 파일도 고칩니다. 규칙은 저장소 최상위 [`CLAUDE.md`](../CLAUDE.md)에 있습니다.

## 개발 방향 — 바꾸려면 먼저 합의

| 원칙 | 내용 |
| --- | --- |
| 서버 코드가 업무 로직의 유일한 출처 | 신고·승인·이력·권한 규칙은 `server/*.js`에만 둡니다. |
| 웹 데모는 서버 코드를 그대로 실행 | `web-demo/`는 `server/*.js`를 **고치지 않고** 서비스 워커 안에서 돌립니다. 서버에 새 Node 모듈(내장 모듈·npm 패키지)을 쓰면 `web-demo/shims/`에 브라우저용 대체 모듈을 만들고 `web-demo/build.mjs`의 `SHIMS`에 등록해야 합니다. |
| 두 가지 실행 방법 | ① 웹에서 바로(웹 데모, 브라우저에 저장) ② 내려받아 실행(Node 서버, SQLite·사진 폴더). 화면 코드의 웹 데모 분기는 `<meta name="app-demo">`·`app-base`가 있을 때만 동작하고, 서버 실행 동작을 바꾸지 않습니다. |
| 기록 보존 | 모든 변경은 트랜잭션 안에서 감사 로그(`audit_log`)와 파손 이벤트(`damage_events`, 변경 전후 스냅샷)를 함께 남깁니다. 이력 있는 데이터는 영구 삭제하지 않습니다. |
| 사진 비공개 | 승인 전 신고 사진은 신고자와 관리자만 봅니다(`/files/photos` 권한 검사). |
| 보안 기본값 | 세션 토큰은 해시로 저장, 쓰기 요청은 CSRF 토큰, 비밀번호 12자 이상. |
| 확인 방법 | `npm test`(통합 테스트 13개)와 `npm run build:web`(웹 데모 빌드)가 통과해야 합니다. 화면이나 서버 동작을 바꾸면 웹 데모도 브라우저로 직접 확인합니다. |

## 다음 할 일 (우선순위순)

### 높음 — 데이터가 틀어지는 문제

- [ ] **병합하면서 "변화 기록"을 고르면 최초 발견일이 덮어써짐** — `server/app.js`의 승인(`/api/reports/:id/approve`)에서 `req.body.change?p:{}`. 2026-10-20 재현: 3/1에 발견한 파손에 9/15 재신고를 합치자 최초 발견일이 9/15로 바뀌고 메모도 덮어써짐. → 병합할 때 `found_at`(과 메모)은 유지.
- [ ] **이벤트 날짜가 항상 입력한 시각** — `server/app.js`의 `event()`. 수리·변화를 며칠 늦게 입력하면 날짜 기준 보기가 틀어집니다. 수리·종료를 실수로 눌렀을 때 되돌릴 방법도 없습니다. → 실제 날짜 입력, 되돌리기(REOPEN) 추가 검토.

### 보통 — 보안·성능·사용성

- [ ] 원본 사진을 EXIF(GPS 위치 등)가 붙은 채 저장·제공 — `server/app.js`의 `savePhotos`. → 원본도 메타데이터를 지우고 저장하거나 원본 내려받기를 관리자로 제한.
- [ ] 사진 한 장을 요청할 때마다 모든 이벤트·신고의 JSON을 파싱 — `server/app.js`의 `/files/photos/:id/:variant`. 데이터가 쌓이면 느려짐. → 사진 테이블이나 색인.
- [ ] 호기를 폐기해도 그 호기 센서의 미처리 신고가 대기 목록에 남음 — `/api/robots/:no/dispose`.
- [ ] 3D 뷰어의 "측면" 버튼이 하나뿐 — damage처럼 **좌측면·우측면**으로 나누기(`public/js/viewer3d.js`의 `setView`). 기준은 "센서가 정면(+Z)을 볼 때"로 damage와 같게.
- [ ] 선·영역 표시가 곡면을 따라가지 않고 직선으로 이어져 반구 창을 관통함, 360° 펼쳐보기 없음 — `viewer3d.js`의 `draw`.
- [ ] 5mm 중복 후보를 화면에서 첫 점끼리만 비교 — `public/js/app.js`의 `updatePick`. → 서버에서 선·영역 전체와의 거리로 계산.
- [ ] 코드가 한 줄에 압축되어 있어 고치기 어려움(`server/app.js` 147줄, `public/js/app.js` 136줄). 크게 고칠 때 그 부분부터 풀어 쓰기(한 번에 전부 바꾸면 변경 내용을 보기 어려움).

### 나중에 · 결정 필요

- [ ] **정정(CORRECTED)을 과거 날짜 보기에도 적용할지** — 지금은 정정한 날 이후에만 반영(테스트 "정정 전 좌표와 날짜 기준 상태 보존"이 이 동작을 고정). "그날 실제로 있던 파손"을 보여 주려면 damage처럼 과거에도 적용해야 합니다. 기획 의도를 정한 뒤 테스트와 함께 바꿉니다.
- [ ] 운영 준비: 실제 시리얼 100개·사이트 목록·장착 위치·원통형 모델명과 치수, 제조사 CAD(GLB) 검수, HTTPS 서버 배포와 백업 예약.
- [ ] 앱 안 QR 스캐너, 이메일·메신저 알림, SSO, 비교 모드, 통계, PDF 리포트, 파손 등급.
- [ ] 웹 데모를 GitHub Actions에서 브라우저로 자동 시험(지금은 빌드만 확인).
