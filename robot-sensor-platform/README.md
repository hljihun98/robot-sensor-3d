# 센서로그 — 로봇 센서 파손 3D 이력관리

첨부된 「로봇 센서 파손 3D 이력관리 플랫폼 기획안」을 기반으로 만든 **서버 저장형 1차 구현**입니다. 브라우저에서 신고하면 서버의 SQLite와 사진 폴더에 저장됩니다. localStorage 데모가 아니며, 실행 중 외부 클라우드·CDN·API가 필요하지 않습니다.

## 웹에서 바로 써 보기

설치 없이 https://hljihun98.github.io/robot-sensor-3d/platform/ 을 열면 이 서버 코드를 브라우저 안에서 그대로 실행하는 웹 데모가 뜹니다. 데이터는 그 브라우저에만 저장되므로 실제 운영은 아래처럼 PC·서버에서 실행하세요. 구조는 [`web-demo/README.md`](web-demo/README.md)에 있습니다.

## Windows에서 바로 실행

1. 이 폴더의 **`START.cmd`를 더블클릭**합니다. Node.js 24 이상이 필요합니다.
2. 브라우저에서 **http://127.0.0.1:3210** 을 엽니다.
3. 첫 실행으로 생성된 **`data/initial-account.txt`** 에서 초기 계정과 임시 비밀번호를 확인합니다.
4. 아이디 `admin`으로 로그인한 후 새 비밀번호를 설정합니다. 임시 비밀번호 안내 파일은 변경 후 삭제하세요.
5. **계정 관리**에서 현장 사용자와 관리자 개인 계정을 발급합니다.

전달한 작업 폴더에는 의존성을 설치해 두었습니다. 소스 ZIP을 다른 컴퓨터에 풀어 실행하면 최초 1회 `npm ci`가 필요하며, `START.cmd`가 자동으로 실행합니다. 이 설치 때만 인터넷 연결이 필요합니다. 실행 중인 콘솔 창을 닫으면 서버가 종료됩니다. 같은 포트에 서버가 이미 켜져 있으면 기존 서버를 이용하세요.

```powershell
npm ci
npm start
```

## 먼저 확인할 데이터

- 1~30호기 등록: 1~5 폐기, 6~30 운영.
- 16호기까지 원통형, 17호기부터 반구형. 31 이후 신규 기본값은 반구형.
- 각 초기 호기에 라이다 2개, D405 카메라 2개의 임시 센서 기록을 생성합니다.
- **실제 센서 시리얼·장착 위치·사이트·파손은 제공되지 않았습니다.** 임시 시리얼 `UNVERIFIED-...`은 실물 번호가 아닙니다. 화면에도 ‘시리얼 미확인’으로 표시합니다.
- 초기 장착일은 프로그램 초기화 시각이며 실물의 과거 장착일을 의미하지 않습니다. 1~5호기는 폐기일이 제공되지 않아 미입력입니다.
- 테스트 데이터와 사진은 실제 운영 DB에 넣지 않았습니다.

## 사용 순서

1. **호기·센서 → 센서 관리 → 시리얼 등록**에서 실물과 임시 센서를 연결합니다.
2. 대량 등록은 `public/sample-sensors.csv` 양식을 내려받아 실제 값으로 바꿉니다. 같은 번호를 여러 행에 중복 입력하거나 잘못된 호기를 포함하면 전체 등록을 취소합니다.
3. 현장 사용자는 **호기 현황 → 센서 → 파손 신고**에서 위치를 찍고 사진·날짜를 제출합니다.
4. 관리자는 **신고 검토**에서 사진과 3D를 나란히 보고 승인합니다. 선·영역은 모양 선택 후 표면을 여러 번 클릭합니다.
5. 기존 파손 재확인은 ‘기존 파손에 합치기’를 선택합니다. 파손이 커졌다면 ‘새 범위로 변화 기록’을 함께 선택합니다.
6. 파손 목록을 선택하면 사진, 발견일, 신고자·확정자, 전체 이력이 나옵니다. 과거 날짜를 선택하면 당시 상태를 확인할 수 있습니다.
7. 수리 후에는 상세의 **수리 완료**에서 사유와 수리 사진을 첨부합니다.
8. 센서 교체 시 기존 센서를 ‘예비로 회수’하면 파손이 그대로 유지됩니다. ‘폐기’하면 해당 센서의 현존 파손이 종료됩니다.

## 3D 모델과 실측 한계

초기 모델은 별도 다운로드 없이 코드로 생성합니다. Mid-360은 65×65×60mm, D405는 42×42×23mm의 주 몸체 치수와 구분된 창·렌즈·브라켓을 사용합니다. 상세 CAD와 장착 브라켓 실측은 반영하지 않은 참고용 형상입니다.

원통형 라이다의 정확한 모델명·치수는 미확정이므로 **80mm 직경 수준의 예시 형상**입니다. 원통형의 좌표, 5mm 중복 판정, 길이 측정은 실측 확인 전 참고값입니다. 사진을 주 증거로 사용하세요.

GLB 교체는 시스템 관리자만 가능합니다. 자체 포함형 GLB 2.0, 2MB 이하, 단위 mm, 센서 중심 원점, +Y 위, +Z 앞, 부위별 메시 이름을 유지하세요. 외부 URI 참조는 거부합니다. 기존 마커 좌표를 자동 재배치하지 않으므로 실물 좌표 정합성 검수가 필요합니다. 운영 모델 교체 전 백업하세요.

## 서버 구성

- Node.js 24 이상, Express 5, 바닐라 JavaScript/CSS
- Three.js / OrbitControls / GLTFLoader / Raycaster
- **Node 내장 `node:sqlite`**: 기획안의 better-sqlite3 대신 사용해 네이티브 모듈 빌드 부담을 줄였습니다. 파일 형식은 동일한 SQLite입니다.
- multer, sharp, bcryptjs, helmet, express-rate-limit
- 인증 코드는 `server/auth.js`에 모아 사내 인증 연동 시 교체 범위를 줄였습니다.

```text
public/                 브라우저 화면·3D·CSS
server/app.js           API·사진 접근·업로드·업무 흐름
server/auth.js          로그인·세션·권한
server/db.js            SQLite 스키마와 초기화
server/validation.js    서버 입력 검증
data/app.db             운영 DB (자동 생성, Git 제외)
data/photos/            원본·화면용·썸네일
data/models/            등록된 GLB
scripts/backup.js       일관된 SQLite 백업 + 사진·모델
scripts/deploy.sh       백업 → git pull → 설치 → PM2 재시작
deploy/                 Nginx / PM2 설정 예시
tests/workflow.test.js  통합 테스트
```

DB 변경과 감사 로그/파손 이벤트는 하나의 트랜잭션으로 저장합니다. 사진 파일을 먼저 기록한 뒤 DB를 커밋하며 실패 시 새 파일을 정리합니다. 프로세스 강제 종료 시 미참조 사진이 남을 수 있으나 확정 기록의 사진을 덮어쓰지는 않습니다.

## 개인 서버 / 사내 서버로 옮기기

개인 서버 OS·도메인·GitHub 저장소가 제공되지 않아 외부 배포나 GitHub 업로드는 하지 않았습니다. 소스와 설정 예시를 포함했습니다.

1. Node.js 24 이상을 설치하고 소스를 복사하거나 자신의 GitHub 저장소에서 받습니다.
2. `npm ci --omit=dev` 후 환경변수를 설정합니다.
3. 외부 접속은 Nginx와 HTTPS 뒤에서 운영하고 `COOKIE_SECURE=true`로 설정합니다.
4. 기존 DB가 있다면 서버를 정지한 상태에서 `data/` 전체를 옮깁니다. 실행 중인 WAL DB의 `app.db`만 복사하지 마세요.
5. 서버 계정이 `data/`를 읽고 쓸 수 있도록 권한을 설정합니다. 데이터를 Git에 넣지 마세요.

| 환경변수 | 기본값 / 용도 |
|---|---|
| `HOST` | `127.0.0.1` · 로컬 접속만 허용 |
| `PORT` | `3210` |
| `DATA_DIR` | 프로그램 폴더의 `data` |
| `PUBLIC_URL` | QR에 들어갈 외부 HTTPS 주소, 예: `https://sensor.example.com` |
| `COOKIE_SECURE` | `false` · HTTPS 운영에서는 `true` 필수 |
| `TRUST_PROXY` | Nginx 한 단계 프록시 환경에서 `1` |
| `INITIAL_ADMIN_PASSWORD` | 새 DB 초기 비밀번호를 환경으로 전달할 때만 선택 사용 |
| `BACKUP_DIR` | 프로그램 폴더의 `backups` |

Docker 사용 시 `docker compose up -d --build`로 실행합니다. 초기 비밀번호는 `docker compose exec sensorlog cat /app/data/initial-account.txt`에서 확인합니다. Docker는 이 환경에서 실행 검증하지 않았습니다. HTTPS 적용 후 Compose의 `COOKIE_SECURE`와 `PUBLIC_URL`을 수정하세요.

PM2는 별도 설치 후 프로젝트 루트에서 `pm2 start deploy/ecosystem.config.cjs`로 시작합니다. 예제는 HTTPS 프록시 운영을 전제로 합니다. HTTPS 없이 로컬 실행할 때는 `npm start`를 사용하세요.

GitHub 저장소를 만들 때 `data/`, `backups/`, `.env`, 초기 계정 파일은 절대 추가하지 마세요. `.gitignore`와 `.dockerignore`에 제외 설정이 있습니다.

## 백업과 복구

```powershell
npm run backup
```

`VACUUM INTO`로 일관된 DB 사본을 만들고 사진·모델을 함께 복사합니다. 완료 표시가 있는 **최근 7회** 백업을 보관합니다. Linux cron 또는 Windows 작업 스케줄러에서 매일 실행하도록 등록할 수 있습니다. 실제 예약 작업은 자동 등록하지 않았습니다.

복구 시 서버를 종료하고, 기존 `data/`를 별도 보관한 다음 완료된 백업의 `app.db`, `photos/`, `models/`를 비어 있는 `data/`에 복사한 뒤 재실행합니다. 기존 WAL/SHM 파일과 백업 DB를 섞지 마세요. 다른 호스트로 복구할 때는 세션 테이블을 비우고 재로그인하는 것을 권장합니다.

## 검증

```powershell
npm ci
npm test
```

통합 테스트는 임시 DB를 사용합니다. 초기 호기 경계, 로그인·비밀번호·CSRF·역할, 신고 및 사진 비공개, 보완·승인·병합, 날짜별 상태와 좌표, 수리, 센서 이동, CSV 롤백, 폐기, 사용 중지, 재시작 영속성을 확인합니다.

별도 QA 데이터로 Chromium에서 로그인, 호기·센서 조회, WebGL 렌더링, 표면 클릭, 사진 신고, 승인, 마커 선택, 점검, 모바일 390px 화면을 확인했습니다. 테스트 사진은 실제 현장 사진이 아닌 단색 테스트 파일입니다. 실제 휴대폰 카메라, 사내 네트워크, 대규모 동시 접속은 별도 현장 검증이 필요합니다.

## 아직 필요한 운영 준비 / 후속 범위

- 실제 시리얼 100개, 사이트 목록, 센서 장착 위치, 원통형 모델명·치수
- 제조사 CAD 검수와 GLB 교체, 실물과 좌표 정합성 확인
- 개인 서버의 OS·도메인·HTTPS·백업 예약 설정
- 앱 내부 카메라 QR 스캐너는 미포함: 휴대폰 기본 카메라로 QR 링크에 접속
- 이메일/메신저 알림, SSO, 비교 모드, 통계, PDF 리포트는 기획안의 후속 범위
- 등급은 DB 값만 비워 두며 자동 진단·관제 연동은 구현하지 않음
