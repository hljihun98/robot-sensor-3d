## 확인한 업무 흐름

1. 첫 로그인 비밀번호 변경과 역할별 접근 권한
2. 1~5 폐기, 6~30 운영, 16/17 라이다 형상 경계
3. 승인 전 신고·사진의 소유자/관리자 제한
4. 3D 표면 선택 → 사진 2장 신고 → 검토 → 승인 → 마커 표시
5. 보완요청·본인 보완과 중복 파손 병합
6. 정정 전후 위치와 날짜별 파손 상태
7. 수리 사진 필수와 수리 후 과거 상태 조회
8. 예비 회수·다른 호기로 재장착할 때 센서 파손 이력 유지
9. 잘못된 CSV 행 포함 시 전체 롤백
10. 호기 폐기 시 센서별 처리와 오등록 삭제 보호
11. 계정 사용 중지 후 기존 세션 차단
12. DB 재시작 후 기록 보존
13. 모바일 목록·상세·이력 탭, 신고 중 고정 버튼 숨김, 가로 넘침 없음
14. 원통형 / Mid-360 / D405의 WebGL 화면과 시점 전환

기획안의 3D 와이어프레임도 시각적으로 확인했습니다. 시험 데이터·단색 시험 사진은 별도의 `work/qa-data-*` DB에서 사용했으며, 실제 사용용 `data/`에는 파손을 등록하지 않았습니다.

## 아직 검증하지 않은 환경

- 물리적 휴대폰의 카메라·멀티터치와 저사양 GPU
- 실제 CAD/GLB 좌표와 현장 센서의 실측 정합성
- Docker / Linux / PM2 / Nginx / HTTPS 실서버 배포
- 다수 현장 사용자의 장시간 동시 접속 및 대량 사진 업로드
- 사내 인증 및 사이트별 접근 정책

현재 계정은 모든 사이트의 승인된 파손을 조회할 수 있습니다. 사이트별 접근 제한이 필요하면 현장 운영 정책을 확정한 뒤 추가해야 합니다.
